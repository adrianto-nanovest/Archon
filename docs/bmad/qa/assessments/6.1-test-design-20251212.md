**Story:** Implement Backend Integration Tests

## Test Strategy Overview

- **Total test scenarios:** 38
- **Unit tests:** 0 (0%) - *This story IS about creating integration tests*
- **Integration tests:** 38 (100%)
- **E2E tests:** 0 (0%) - *Backend-only; no UI paths*
- **Priority distribution:** P0: 12, P1: 16, P2: 8, P3: 2

### Strategic Assessment

Story 6.1 is **meta-testing** - creating integration tests to validate the Confluence sync workflow. The "tests" designed here ARE the test implementations to be built. The acceptance criteria map directly to test categories that must be implemented.

**Key Distinction:**
- **Unit tests** (existing): `test_confluence_sync_service.py`, `test_deletion_detection.py` - Mock all dependencies
- **Integration tests** (this story): Real database operations with mocked Confluence API only

    Recommendation: Use Docker PostgreSQL + run migration 010

@pytest.fixture
async def clean_database(test_database):
    """Clean database between tests to ensure isolation."""
    await test_database.from_("confluence_pages").delete().neq("page_id", "")
    await test_database.from_("archon_crawled_pages").delete().filter(
        "metadata->>'page_id'", "is not", "null"

    yield test_database
