# Story 2.2: High-Value Macro Handlers (Enhanced with Docling)

## Status
Done

## Story

**As a** backend developer,
**I want** to implement 6 RAG-critical macro handlers for Confluence content extraction, including AI-powered attachment processing,
**so that** code blocks, panels, JIRA issues, attachments (with full-text content), and embedded content are preserved in searchable format.

## Acceptance Criteria

1. **Code Macro Handler** (~100 lines): Extract language tags, unwrap CDATA, preserve whitespace (NO strip)
2. **Panel Macro Handler** (~120 lines): Support info/note/warning/tip with emoji prefixes (ℹ️✅⚠️❌), blockquote formatting
3. **JIRA Macro Handler - 3-Tier Extraction** (~150 lines):
   - Tier 1: Macro parameter extraction (~40% coverage)
   - Tier 2: URL pattern matching in `<a>` tags (~30% coverage)
   - Tier 3: Plain text regex on final markdown (~30% coverage)
   - Deduplication across all tiers
   - JQL table handling (if JIRA client provided)
4. **Attachment Macro Handler with Docling Integration** (~200 lines):
   - Extract filenames, map file type to emoji icons (📄📝📊📦📎)
   - **Download attachments from Confluence API**
   - **Process PDF, DOCX, PPTX, XLSX with DoclingProcessor (Story 2.6 dependency)**
   - **Extract full-text content and embed in page markdown**
   - **Enrich metadata with document structure (page_count, table_count, code_blocks, word_count)**
   - **Graceful fallback to file link if Docling processing fails**
   - **Respect file size limits (skip files > 50MB)**
   - **Background processing mode (don't block page sync)**
5. **Embed Macro Handler** (~120 lines): Convert embed URLs for 15+ platforms (YouTube, Vimeo, Google Maps, etc.)
6. **Generic Macro Handler** (~80 lines): Fallback for unknown macros with parameter extraction

#### BaseMacroHandler Abstract Class Pattern

**From Story 2.1** (python/src/server/services/confluence/macro_handlers/base.py:14):
```python
from abc import ABC, abstractmethod
from bs4 import Tag

class BaseMacroHandler(ABC):
    """Base class for Confluence macro handlers with error isolation."""

    @abstractmethod
    async def process(self, macro_tag: Tag, page_id: str, space_id: str = None):
        """
        Process a single Confluence macro tag.

        Args:
            macro_tag: BeautifulSoup Tag object representing <ac:structured-macro>
            page_id: Confluence page ID (for logging context)
            space_id: Confluence space ID (optional, for API calls)

        Returns:
            None (modifies macro_tag in-place via BeautifulSoup)
        """
        raise NotImplementedError("Subclasses must implement process()")
```

#### Concrete Handler Example: Code Macro

**Production Code Reference:** Lines 74-107

**Implementation Pattern:**
```python
from .base import BaseMacroHandler
from bs4 import NavigableString

class CodeMacroHandler(BaseMacroHandler):
    async def process(self, macro_tag, page_id, space_id=None):
        # Extract language parameter
        language_param = macro_tag.find('ac:parameter', {'ac:name': 'language'})
        language = language_param.get_text() if language_param else ''

        # Extract code content from CDATA
        code_body = macro_tag.find('ac:plain-text-body')
        code_content = code_body.get_text(strip=False) if code_body else ''

        # Build markdown code block
        markdown_code = f"```{language}\n{code_content}\n```"

        # Replace macro tag in-place
        macro_tag.replace_with(NavigableString(markdown_code))
```

**Critical Pattern:** Handlers use `macro_tag.replace_with()` for in-place DOM modifications. NO return value needed.

### Architecture Context: JIRA 3-Tier Extraction Strategy (CRITICAL)

**Source:** [docs/bmad/brownfield-prd/epic-2-html-to-markdown-content-processing.md](docs/bmad/brownfield-prd/epic-2-html-to-markdown-content-processing.md#328-three-tier-jira-extraction-critical)

# Extract from <a href="https://jira.company.com/browse/PROJ-123">

### Architecture Context: Docling Integration for Attachment Processing

**Source:** [docs/bmad/docling-confluence-asset-processing-analysis.md](docs/bmad/docling-confluence-asset-processing-analysis.md)

**Docling Capabilities:**
- **Advanced PDF Processing**: Layout analysis, table structure (TableFormer), code block detection
- **Office Format Support**: DOCX, PPTX, XLSX with structure preservation
- **Metadata Extraction**: Page count, table count, code block count, word count
- **Export Formats**: Markdown (RAG-optimized), JSON, Plain Text

**Integration Pattern (Story 2.2):**

```python
class AttachmentMacroHandler(BaseMacroHandler):
    def __init__(self, confluence_client, docling_processor, asset_links_tracker, settings):
        self.confluence_client = confluence_client
        self.docling_processor = docling_processor  # From Story 2.6
        self.asset_links_tracker = asset_links_tracker
        self.settings = settings

    async def process(self, macro_tag, page_id, space_id=None):
        filename = self._extract_filename(macro_tag)

        # Add to asset_links metadata
        self.asset_links_tracker.append({
            "filename": filename,
            "file_type": self._get_file_type(filename),
            "processed": False
        })

        # Check if Docling processing should be attempted
        if (self.settings.docling_enabled and
            self._is_docling_supported(filename) and
            page_id):

            # Download attachment
            file_path = await self.confluence_client.download_attachment(page_id, filename)

            # Process with Docling (Story 2.6 service)
            result = await self.docling_processor.process_attachment(file_path, page_id)

            if result["success"]:
                # Update metadata with Docling output
                self.asset_links_tracker[-1].update({
                    "processed": True,
                    "page_count": result["metadata"].get("page_count"),
                    "table_count": result["metadata"].get("table_count"),
                    "word_count": result["metadata"].get("word_count")
                })

                # Embed full-text content in page markdown
                markdown = f"\n\n<!-- ATTACHMENT: {filename} -->\n{result['markdown']}\n"
                macro_tag.replace_with(NavigableString(markdown))
            else:
                # Graceful fallback to file link
                icon = self._get_file_icon(filename)
                markdown = f"[{icon} {filename}](ATTACHMENT_PLACEHOLDER_{filename})"
                macro_tag.replace_with(NavigableString(markdown))
        else:
            # Docling disabled or unsupported format
            icon = self._get_file_icon(filename)
            markdown = f"[{icon} {filename}](ATTACHMENT_PLACEHOLDER_{filename})"
            macro_tag.replace_with(NavigableString(markdown))
```

**Performance Considerations (from Story 2.6):**
- **File Size Limits**: Skip files > 50MB (configurable via `settings.docling_max_file_size_mb`)
- **Timeout Protection**: 60-second max per file (Story 2.6 enforces via `asyncio.wait_for()`)
- **Concurrency Limits**: Max 2 concurrent Docling processes (Story 2.6 Semaphore)
- **Graceful Degradation**: Always fall back to file link on error

**Supported Formats:**
- **Documents** (Docling processing): `.pdf`, `.docx`, `.pptx`, `.xlsx`
- **Unsupported formats** (file link only): `.doc`, `.xls`, `.ppt`, `.txt`, `.md`, `.zip`, etc.
