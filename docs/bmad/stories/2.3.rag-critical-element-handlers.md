# Story 2.3: RAG-Critical Element Handlers (Enhanced with Multimodal LLM)

## Status
Approved

## Story

**As a** backend developer,
**I want** to implement 4 element handlers with bulk API call optimization and AI-powered image understanding,
**so that** user mentions, page links, images (with searchable text), and simple elements are processed efficiently without N+1 query anti-pattern.

## Acceptance Criteria

1. **Link Handler** (~120 lines):
   - Internal page links: Bulk API call for all unique page titles (single call)
   - External links: Filter http/https, deduplicate JIRA links, add Google Drive icons
   - Store metadata: `internal_links` (page_id, title, url), `external_links` (title, url)

2. **User Handler** (~100 lines):
   - Extract unique account IDs (deduplication)
   - **Bulk API call**: `get_users_by_account_ids(account_ids)` (single call for all users)
   - Cache user information to avoid duplicate lookups
   - Store metadata: `user_mentions` (account_id, display_name, profile_url)

3. **Image Handler with AI Processing** (~130 lines):
   - Detect `<ac:image>` with two sources: `<ri:attachment>` (local) and `<ri:url>` (external)
   - Determine type by extension: Images (🖼️), Videos (🎬), Other (📎)
   - Add to `asset_links` metadata if attachment
   - **DEFAULT: Multimodal LLM processing** (when `image_processing_mode = "multimodal"`):
     - Use MODEL_CHOICE from RAG Settings > Chat Model to determine LLM
     - Check if selected model supports multimodal (vision) capabilities
     - If multimodal supported: Send image with prompt: "Extract all visible text from this image. Identify the image type (chart, diagram, screenshot, photo). Describe key elements in 1-2 sentences."
     - Extract searchable text from screenshots/diagrams
     - Image classification (chart, diagram, photo, etc.)
     - Embed analysis in markdown comments for searchability
     - **FAST**: API call (~1-2 seconds), no local processing overhead
   - **FALLBACK: Docling OCR** (when model lacks multimodal support OR `image_processing_mode = "docling_ocr"`):
     - Automatically triggered if MODEL_CHOICE doesn't support vision
     - Process images with DoclingProcessor OCR
     - Extract text using EasyOCR/Tesseract
     - Slower (~30-60s per image), useful for non-multimodal models or air-gapped deployments
   - **Graceful fallback if both fail**: Standard image markdown with filename only

4. **Simple Element Handler (Simplified)** (~80 lines):
   - Emoticons: Use `ac:emoji-fallback` attribute only (skip shortname - low RAG value)
   - Inline Comments: Strip `<ac:inline-comment-marker>` entirely (collaborative metadata, not content)
   - Time Elements: Use text content only (skip ISO datetime parsing - minimal RAG value)

#### BaseElementHandler Abstract Class Pattern

**From Story 2.1** (python/src/server/services/confluence/element_handlers/base.py:14):
```python
from abc import ABC, abstractmethod
from bs4 import BeautifulSoup

class BaseElementHandler(ABC):
    """Base class for Confluence element handlers with error isolation."""

    @abstractmethod
    async def process(self, soup: BeautifulSoup, page_id: str, space_id: str = None):
        """
        Process all elements of this type in the soup.

        Args:
            soup: BeautifulSoup object (entire page HTML)
            page_id: Confluence page ID (for logging context)
            space_id: Confluence space ID (for API calls)

        Returns:
            None (modifies soup in-place via BeautifulSoup)
        """
        raise NotImplementedError("Subclasses must implement process()")
```

**Key Difference from Macro Handlers:**
- Macro handlers process SINGLE macro tag at a time
- Element handlers process ALL elements of that type in entire soup (full-page context)

### Architecture Context: Bulk API Call Pattern (CRITICAL)

**Source:** [docs/bmad/brownfield-prd/epic-2-html-to-markdown-content-processing.md](docs/bmad/brownfield-prd/epic-2-html-to-markdown-content-processing.md#361-bulk-api-calls-performance-optimization)

**Problem:** N+1 query anti-pattern for user/page resolution
- 100 user mentions = 100 individual API calls → **SLOW**
- 50 page links = 50 individual API calls → **SLOW**

**Solution:** Three-phase processing pattern

**Phase 1: Collection** (Lines 430-480 in production code)
```python
async def process(self, soup, page_id, space_id):
    # PHASE 1: Collect all unique identifiers
    page_titles = set()
    page_elements = soup.find_all('ri:page')
    for elem in page_elements:
        title = elem.get('ri:content-title')
        if title:
            page_titles.add(title)

    # Deduplicate to unique list
    unique_titles = list(page_titles)
```

**Phase 2: Bulk API Call** (Lines 481-510)
```python
    # PHASE 2: Single bulk API call
    if self.confluence_client and space_id and unique_titles:
        page_mapping = await self.confluence_client.find_pages_by_titles(space_id, unique_titles)
        # Returns: {title: {page_id, url}}
    else:
        # Placeholder mapping if no client
        page_mapping = {title: {"page_id": None, "url": None} for title in unique_titles}
```

**Phase 3: Resolution** (Lines 511-550)
```python
    # PHASE 3: Process all elements with cached results
    for elem in page_elements:
        title = elem.get('ri:content-title')
        page_info = page_mapping.get(title, {})

        # Replace element with markdown link
        link_text = elem.get_text() or title
        url = page_info.get('url') or f"PLACEHOLDER_{title}"
        markdown_link = f"[{link_text}]({url})"
        elem.replace_with(NavigableString(markdown_link))

        # Add to metadata tracker
        self.internal_links_tracker.append({
            "page_id": page_info.get('page_id'),
            "title": title,
            "url": page_info.get('url')
        })
```

**Performance Impact:**
- **Before:** 100 API calls for 100 items → ~10-30 seconds
- **After:** 1 API call for 100 items → ~0.1-0.3 seconds
- **Speedup:** 50x faster

**Same Pattern for User Resolution:**
- Phase 1: Collect unique account IDs
- Phase 2: Bulk API call `get_users_by_account_ids(account_ids)` → `{account_id: {display_name, email, profile_url}}`
- Phase 3: Process all `<ri:user>` elements with cached results

```python
async def _process_image_with_multimodal_llm(self, page_id, filename, image_element):
    # Download image
    file_path = await self.confluence_client.download_attachment(page_id, filename)

    # Read image as base64 (required for LLM API)
    import base64
    with open(file_path, "rb") as f:
        image_data = base64.b64encode(f.read()).decode("utf-8")

    # Construct multimodal prompt
    prompt = """Extract all visible text from this image. Identify the image type (chart, diagram, screenshot, photo). Describe key elements in 1-2 sentences."""

    # Call LLM provider with image (uses MODEL_CHOICE from settings)
    # Example: gpt-4o, claude-3-opus, gemini-1.5-pro
    response = await self.llm_provider_service.chat_with_image(
        model=self.model_choice,
        prompt=prompt,
        image_data=image_data,
        image_type="base64"
    )

    # Parse response (structured output)
    analysis = {
        "extracted_text": response.get("text_content", ""),
        "image_type": response.get("image_type", "unknown"),  # chart, diagram, photo, screenshot
        "description": response.get("description", ""),
        "processor": "multimodal_llm",
```

```python
async def html_to_markdown(self, html: str, page_id: str, space_id: str = None):
    soup = BeautifulSoup(html, 'html.parser')

async def _process_elements(self, soup, page_id, space_id):
    """Process all element handlers in order."""
    for handler in self.element_handlers:
        try:
            await handler.process(soup, page_id, space_id)

            )
```
