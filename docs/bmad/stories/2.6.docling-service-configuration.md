# Story 2.6: Docling Service & Configuration

## Status
Done

## Story

**As a** backend developer,
**I want** to create a reusable Docling service layer with configuration and error handling,
**so that** attachment handlers can process PDF/Office documents efficiently, and image handlers have OCR fallback option.

## Acceptance Criteria

1. **DoclingProcessor Service** (~120 lines):
   - Initialize DocumentConverter with optimized pipeline options
   - **PRIMARY USE: PDF/Office document processing** (DOCX, PPTX, XLSX)
   - **SECONDARY USE: Image OCR fallback** (opt-in when multimodal LLM unavailable)
   - Implement `async process_attachment(file_path: Path) -> dict` method
   - Implement `async process_image_ocr(file_path: Path) -> dict` method (fallback only)
   - Extract metadata helper: `_extract_metadata(doc: DoclingDocument) -> dict`
   - Return structured response: `{success: bool, markdown: str, plain_text: str, metadata: dict, error: str}`
2. **Configuration Settings** (add to `ConfluenceSettings`):
   - `docling_enabled: bool = True` - Master feature flag for PDF/Office processing
   - `image_processing_mode: str = "multimodal"` - Options: "multimodal" (default, uses MODEL_CHOICE), "docling_ocr" (force OCR), "none"
   - `docling_max_file_size_mb: int = 50` - Skip files larger than this
   - `docling_timeout_seconds: int = 60` - Processing timeout per file
   - `docling_max_concurrent: int = 2` - Limit parallel Docling processes (memory management)
3. **Format Detection & Fallback**:
   - **Documents** (always Docling): `.pdf`, `.docx`, `.pptx`, `.xlsx`
   - **Images** (multimodal LLM if supported, else Docling OCR): `.png`, `.jpg`, `.jpeg`, `.tiff`, `.webp`
   - Check MODEL_CHOICE capabilities at runtime to determine fallback path
   - Unsupported formats: graceful fallback to file link
   - Clear logging for unsupported formats and multimodal capability checks
4. **Async Attachment Download**:
   - Download attachment from Confluence API to temp directory
   - Return `Path` object for processing
   - Cleanup temp files after processing
5. **Comprehensive Error Handling**:
   - Try-except wrapper around all Docling calls
   - Timeout handling (prevent infinite processing)
   - Memory exhaustion detection (file too large)
   - Graceful degradation on any error
   - Detailed error logging with context (filename, page_id, error type)
6. **Metadata Extraction Helpers**:
   - Extract page_count, table_count, code_block_count, image_count
   - Extract has_code, has_formulas flags
   - Extract document_structure (sections, headings, TOC)
   - Return dict matching asset_links metadata schema

### Architecture Context: Async/Await Patterns

**Source:** [docs/bmad/brownfield-architecture/high-level-architecture.md](docs/bmad/brownfield-architecture/high-level-architecture.md#actual-tech-stack)

**Framework:** FastAPI 0.104+ (async-first with lifespan events)

**Async Patterns in Archon:**
- All service methods are `async def` (even if not I/O bound)
- CPU-bound operations (like Docling processing) use `asyncio.to_thread()` or `concurrent.futures.ThreadPoolExecutor`
- Semaphore pattern for concurrency limiting

**Example CPU-bound Task in Async Context:**
```python
import asyncio
from concurrent.futures import ThreadPoolExecutor

class DoclingProcessor:
    def __init__(self):
        self._executor = ThreadPoolExecutor(max_workers=2)

    async def process_attachment(self, file_path: Path) -> dict:
        # Run CPU-bound Docling processing in thread pool
        loop = asyncio.get_event_loop()
        result = await loop.run_in_executor(
            self._executor,
            self._process_sync,  # Synchronous Docling call
            file_path
        )
        return result

    def _process_sync(self, file_path: Path):
        """Synchronous Docling processing (CPU-bound)."""
        result = self.converter.convert(str(file_path))
        return {
            "success": True,
            "markdown": result.document.export_to_markdown(),
            "metadata": self._extract_metadata(result.document)
        }
```

**Semaphore Pattern for Concurrency Limiting:**
```python
import asyncio

class DoclingProcessor:
    def __init__(self):
        self._semaphore = asyncio.Semaphore(2)  # Max 2 concurrent processes

    async def process_attachment(self, file_path: Path) -> dict:
        async with self._semaphore:
            # Only 2 processes can execute this block simultaneously
            result = await self._process_with_timeout(file_path)
            return result
```

**Timeout Pattern:**
```python
import asyncio

async def process_with_timeout(self, file_path: Path) -> dict:
    try:
        result = await asyncio.wait_for(
            self._process_async(file_path),
            timeout=settings.docling_timeout_seconds
        )
        return result
    except asyncio.TimeoutError:
        self.logger.warning(f"Docling processing timeout for {file_path.name}")
        return {"success": False, "error": "Processing timeout"}
```

### Architecture Context: Error Handling and Logging

**Source:** [docs/bmad/brownfield-architecture/high-level-architecture.md](docs/bmad/brownfield-architecture/high-level-architecture.md#actual-tech-stack)

**Logging Standards:**
- Use Python's built-in `logging` module (no third-party logging libraries)
- Logger name: `"DoclingProcessor"` (class name)
- Log levels:
  - `DEBUG`: Verbose processing details (pipeline options, document structure)
  - `INFO`: Processing milestones (file start/complete, format detection)
  - `WARNING`: Recoverable errors (file too large, unsupported format, timeout)
  - `ERROR`: Processing failures (Docling exception, memory exhaustion) with `exc_info=True`

**Error Handling Pattern:**
```python
import logging

class DoclingProcessor:
    def __init__(self):
        self.logger = logging.getLogger("DoclingProcessor")

    async def process_attachment(self, file_path: Path, page_id: str = None) -> dict:
        self.logger.info(f"Starting Docling processing for {file_path.name} (page_id={page_id})")

        try:
            # Check file size
            file_size_mb = file_path.stat().st_size / (1024 * 1024)
            if file_size_mb > settings.docling_max_file_size_mb:
                self.logger.warning(
                    f"Skipping {file_path.name}: file size {file_size_mb:.2f}MB exceeds limit {settings.docling_max_file_size_mb}MB"
                )
                return {"success": False, "error": f"File too large ({file_size_mb:.2f}MB)"}

            # Process with Docling
            result = await self._process_with_timeout(file_path)

            self.logger.info(f"Completed Docling processing for {file_path.name}")
            return result

        except TimeoutError:
            self.logger.warning(f"Timeout processing {file_path.name} (page_id={page_id})")
            return {"success": False, "error": "Processing timeout"}

        except MemoryError:
            self.logger.error(
                f"Memory exhausted processing {file_path.name} (page_id={page_id})",
                exc_info=True
            )
            return {"success": False, "error": "Memory exhausted"}

        except Exception as e:
            self.logger.error(
                f"Failed to process {file_path.name} (page_id={page_id}): {e}",
                exc_info=True  # Full traceback for debugging
            )
            return {"success": False, "error": str(e)}
```

**Graceful Degradation Strategy:**
- Always return structured dict: `{"success": bool, ..., "error": str | None}`
- Never raise exceptions to caller (except for critical system failures)
- Log errors with full context (filename, page_id, error type, traceback)
- Handlers check `result["success"]` and fall back to file link if False

   - Use MODEL_CHOICE from RAG Settings to determine LLM
   - Check if selected model supports multimodal (vision) capabilities
   - If multimodal supported: Send image with prompt for text extraction + classification
   - **FAST**: API call (~1-2 seconds), no local processing overhead
   - **ACCURATE**: >90% accuracy for text extraction + image classification

2. **FALLBACK: Docling OCR** (automatic for non-multimodal models OR `image_processing_mode = "docling_ocr"`)
   - Automatically triggered if MODEL_CHOICE doesn't support vision
   - Process images with DoclingProcessor OCR (EasyOCR/Tesseract)
   - Extract text using local OCR engines
   - **SLOWER**: ~30-60s per image
   - **ACCURATE**: >85% accuracy for printed text

3. **FINAL FALLBACK**: Standard image markdown (if both fail)

**Multimodal Model Detection:**
```python
def _supports_multimodal(self, model_choice: str) -> bool:
    """Check if MODEL_CHOICE supports vision/multimodal capabilities."""
    multimodal_models = {
        "gpt-4o", "gpt-4-vision", "gpt-4-turbo",
        "claude-3-opus", "claude-3-sonnet", "claude-3-haiku",
        "gemini-pro-vision", "gemini-1.5-pro", "gemini-2.0-flash"
    }
    return any(model in model_choice.lower() for model in multimodal_models)
```

### Architecture Context: Performance Considerations and Mitigation

**Source:** [docs/bmad/docling-confluence-asset-processing-analysis.md](docs/bmad/docling-confluence-asset-processing-analysis.md#risks-and-considerations)

**Processing Times (CPU):**
- Simple PDF (10 pages): ~2-3 seconds
- Complex PDF with tables: ~5-10 seconds
- Scanned PDF with OCR: ~30-60 seconds
- Office documents (DOCX, PPTX, XLSX): ~1-2 seconds
- Image with OCR: ~30-60 seconds (EasyOCR)

**Memory Usage:**
- Peak memory: 2-3GB per document processing
- Multiple parallel processes: Memory multiplies (2 concurrent = 4-6GB peak)

**Mitigation Strategies (Story 2.6 Implementation):**
1. **File Size Limits** - Skip files > 50MB (configurable)
2. **Timeout Protection** - 60-second max processing time per file (configurable)
3. **Concurrency Limits** - Max 2 concurrent Docling processes (asyncio.Semaphore)
4. **Graceful Degradation** - Always fall back to file link on error
5. **Feature Flag** - `docling_enabled` for opt-out control

**Two-Phase Processing Strategy (Story 2.2):**
```python
# Phase 1: Quick sync (HTML content only) - NEVER BLOCK
markdown_content, metadata = await processor.html_to_markdown(page_id)
await store_page(page_id, markdown_content, metadata)

# Phase 2: Background attachment processing - ASYNC
if settings.docling_enabled:
    asyncio.create_task(process_attachments_background(page_id))
```

**Key Insight:**
- DoclingProcessor should NOT implement background processing logic (that's Story 2.2's AttachmentMacroHandler)
- DoclingProcessor provides synchronous-style async methods (callable from background tasks)
- AttachmentMacroHandler decides when to process attachments (immediately vs background)
