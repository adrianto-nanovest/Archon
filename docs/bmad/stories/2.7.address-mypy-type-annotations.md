### Architecture Context: Python Type Hinting Standards

**Source:** [docs/bmad/brownfield-architecture/high-level-architecture.md#actual-tech-stack](docs/bmad/brownfield-architecture/high-level-architecture.md#actual-tech-stack)

**Python Version:** 3.12 (required for modern type hinting features)
**Type Checking Tool:** MyPy 1.17.0+ (included in dev dependencies)

#### Python 3.12 Union Syntax

Use modern union syntax (PEP 604) instead of `typing.Optional`:

```python
# ✅ CORRECT: Python 3.12 union syntax
def process(self, soup: BeautifulSoup, space_id: str | None = None) -> None:
    pass

# ❌ DEPRECATED: typing.Optional (pre-3.10)
from typing import Optional
def process(self, soup: BeautifulSoup, space_id: Optional[str] = None) -> None:
    pass
```

**Rationale:** Python 3.12 native union types are more concise, readable, and avoid typing module imports.

#### Abstract Base Class Return Types

All abstract methods must specify return types for type checking:

```python
from abc import ABC, abstractmethod

class BaseMacroHandler(ABC):
    @abstractmethod
    async def process(self, macro_tag: Tag, page_id: str, space_id: str | None = None) -> None:
        """
        Process a single Confluence macro tag.

        Returns:
            None (modifies macro_tag in-place via BeautifulSoup)
        """
        raise NotImplementedError(...)
```

**Key Points:**
- `-> None:` is required even when method doesn't return anything
- Return type must match implementation (in-place modification = None)
- Docstring "Returns:" section should also state "None" with explanation

### Technical Constraints: BeautifulSoup4 Type Stubs Issue

**Known Issue:** BeautifulSoup4 does not explicitly export `NavigableString` in type stubs

**Evidence:**
- TypeShed issue: https://github.com/python/typeshed/issues/4968
- BeautifulSoup4 version: Latest (4.12+)
- MyPy warning: `error: Module "bs4" does not explicitly export attribute "NavigableString"`

**Root Cause:**
- BeautifulSoup4's `__init__.py` imports `NavigableString` from `bs4.element`
- Type stubs in typeshed don't include `NavigableString` in `__all__` export
- MyPy treats missing `__all__` entry as "not exported" even though runtime works

**Solution Approaches:**

1. **Type Ignore with Justification (RECOMMENDED):**
   ```python
   # BeautifulSoup4 doesn't explicitly export NavigableString in type stubs,
   # but it's available at runtime via bs4/__init__.py import from bs4.element.
   # See: https://github.com/python/typeshed/issues/4968
   from bs4 import NavigableString  # type: ignore[import]
   ```

2. **Direct Element Module Import (ALTERNATIVE):**
   ```python
   # Import directly from bs4.element (where NavigableString is defined)
   from bs4.element import NavigableString
   ```
   **Trade-off:** More explicit but diverges from standard BS4 usage patterns

3. **Conditional Import for Type Checking (OVERKILL):**
   ```python
   from typing import TYPE_CHECKING
   if TYPE_CHECKING:
       from bs4 import NavigableString
   else:
       from bs4.element import NavigableString
   ```
   **Trade-off:** Complex and unnecessary for our use case

**Chosen Approach:** Option 1 (Type Ignore with Justification)
- Matches standard BeautifulSoup4 usage patterns
- Clear documentation of why type ignore is needed
- Doesn't require code structure changes
