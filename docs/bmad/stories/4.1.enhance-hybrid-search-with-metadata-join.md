    ```python
    async def _fetch_confluence_metadata(
        self,
        page_ids: list[str]
    ) -> dict[str, dict[str, Any]]:
        """
        Fetch Confluence metadata for given page IDs.

        Args:
            page_ids: List of Confluence page IDs to fetch metadata for

        Returns:
            Dict mapping page_id to metadata dict containing:
            - space_key, title, path, jira_issue_links, user_mentions
        """
        if not page_ids:
            return {}

        # Batch query confluence_pages table
        response = self.supabase_client.from_("confluence_pages").select(
            "page_id, space_key, title, path, metadata"
        ).in_("page_id", page_ids).eq("is_deleted", False).execute()

        result = {}
        for row in response.data:
            metadata = row.get("metadata", {})
            result[row["page_id"]] = {
                "space_key": row["space_key"],
                "title": row["title"],
                "path": row["path"],
                "jira_issue_links": metadata.get("jira_issue_links", []),
                "user_mentions": metadata.get("user_mentions", []),
                "ancestors": metadata.get("ancestors", []),
                "internal_links": metadata.get("internal_links", [])
            }
        return result
    ```

### Technical Constraints and Design Decisions

**Why Post-Processing Instead of SQL Function Modification?**
- **Simpler Rollback**: Python changes don't require migration rollback
- **Separation of Concerns**: Search logic stays in Python, SQL handles raw data
- **Batch Efficiency**: Single IN query for all page_ids (not N+1)
- **Backward Compatibility**: Existing RPC callers unaffected
- **Incremental Enhancement**: Story 4.2 will add filtering (easier in Python)

**Why LEFT JOIN Pattern Instead of INNER JOIN?**
- Non-Confluence chunks must still return with null metadata
- Search should not fail if confluence_pages record is missing
- Matches Epic 4 requirement: "Return metadata for Confluence chunks only (null for web/upload)"

**Performance Considerations:**
- **Index Usage**: `idx_crawled_pages_confluence_page_id` ensures fast page_id lookups
- **Batch Query**: Single query with IN clause for all page_ids (not per-chunk)
- **Target Overhead**: <50ms for metadata enrichment (measured via span)
- **P95 Latency**: Must remain <500ms with Confluence metadata

**Security Considerations:**
- Use Supabase SDK query builder (parameterized queries)
- Do NOT construct raw SQL strings with user input
- Validate page_ids are strings before query
